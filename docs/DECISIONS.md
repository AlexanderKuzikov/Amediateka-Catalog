# Amediateka Catalog — DECISIONS

<!-- Append-only. Формат фиксирован. -->

## 2026-11-05: Данные как снимок, HTML как артефакт сборки

**Контекст:** каталог должен обновляться без ручного редактирования HTML.

**Решение:** `scripts/fetch.mjs` сохраняет нормализованный снимок в `data/series.json`, `scripts/build.mjs` генерирует оба HTML из `src/template.html`. `dist/` не редактируется руками.

**Альтернативы:** генерировать HTML сразу из API без промежуточного JSON; хранить данные только в HTML.

**Trade-off:** в репозитории лежит снимок данных, но сборка воспроизводима и работает без сети.

## 2026-11-05: Два варианта вывода

**Контекст:** нужен и обычный статический каталог, и вариант с JSON внутри HTML.

**Решение:** один шаблон собирается дважды: `amediateka_catalog.html` со строками в разметке и `amediateka_catalog_json.html` со `<script type="application/json" id="catalog-data">`. JSON-вариант строит строки и карточки в рантайме.

**Альтернативы:** дублировать шаблоны; добавлять JSON в статическую версию поверх строк.

**Trade-off:** в шаблоне есть рендерер строк для JSON-варианта, дублирующий серверную генерацию разметки.

## 2026-11-05: Постеры productPosterV2

**Контекст:** `productPoster` у Amediateka бывает letterbox-версией с серой плашкой и обрезанным текстом.

**Решение:** приоритет постеров: `productPosterV2` → `v_poster` → `productPoster` → `partnersPoster` → `productItemCover`. Все 382 сериала получили V2.

**Альтернативы:** оставить V1 для совместимости с сайтом.

**Trade-off:** у части сериалов нет промо-бейджа «премьера» на постере.

## 2026-11-05: Фолбэк сортировки внешних рейтингов

**Контекст:** у свежих сериалов часто нет IMDb и Кинопоиска, из-за чего сортировка по ним ставит новинки в конец.

**Решение:** при сортировке по IMDb или КП отсутствующий рейтинг заменяется рейтингом Amediateka. В интерфейсе значение остаётся «—» с подсказкой.

**Альтернативы:** оставлять пустые значения в конце; скрывать такие сериалы.

**Trade-off:** верх списка по IMDb может содержать сериалы без IMDb; это осознанно.

## 2026-11-05: Страны только из detail-эндпоинта

**Контекст:** список сериалов не содержит стран, они есть только в детальном ответе.

**Решение:** сборщик всегда запрашивает detail для каждого сериала (382 запроса, около 25 секунд локально). Это же даёт самые свежие рейтинги, сезоны и описания.

**Альтернативы:** тянуть страны только для новых сериалов; не добавлять фильтр стран.

**Trade-off:** ежемесячная сборка делает больше запросов к API.

## 2026-11-05: GitHub Actions вместо локального планировщика

**Контекст:** сборка должна быть ежемесячной и публичной.

**Решение:** workflow `.github/workflows/monthly.yml` запускается 1-го числа в 03:17 UTC и вручную, обновляет `data/` и `dist/`, коммитит в `main`.

**Альтернативы:** Windows Task Scheduler локально; внешний cron.

**Trade-off:** доступность API с GitHub runner не проверена; при блокировке нужен локальный запуск `npm run monthly`.

## 2026-11-05: Локальный планировщик вместо GitHub Actions

**Контекст:** API Amediateka отдаёт 403 с GitHub runner (гео/антибот), поэтому workflow не может обновлять данные. Заменяет решение о GitHub Actions.

**Решение:** workflow удалён. Обновление выполняет Windows Task Scheduler: ежедневная проверка в 10:17, fetch/build/commit/push только если снимок данных не за текущий месяц. Регистрация — `scripts/install-task.ps1`, пропуск запуска компенсируется `StartWhenAvailable`.

**Альтернативы:** прокси с российским IP, self-hosted runner, внешний cron.

**Trade-off:** автообновление требует включённого ПК и входа пользователя; публичная CI-сборка недоступна.

## 2026-11-05: Секция «Новое за месяц» на addedAt

**Контекст:** нужен блок новинок в ежемесячном каталоге.

**Решение:** fetch сохраняет дату первого появления «addedAt»; build считает новыми сериалы с addedAt за последние 30 дней и передаёт флаг в HTML и JSON. Секция показывает горизонтальную ленту, бейджи «новое» на постерах, открывает лайтбокс.

**Альтернативы:** сравнивать с предыдущим снимком при каждом билде; показывать премьеры года без точной даты.

**Trade-off:** на первом запуске 12 новинок посеяны по диффу с июльским снимком; точная дата их появления неизвестна.

## 2026-11-05: Новинки по publicationDate

**Контекст:** seed по июльскому снимку давал приблизительные даты и не учитывал фильмы.

**Решение:** `addedAt` берётся из `publicationDate` detail-ответа, fallback — предыдущее значение или дата сборки. Секция «Новое за месяц» показывает тайтлы с `addedAt` за последние 30 дней.

**Альтернативы:** diff между снимками; seed по старому JSON.

**Trade-off:** обновление метаданных на платформе может подсветить старый тайтл как новый.

## 2026-11-05: Добавлены фильмы

**Контекст:** каталог содержал только сериалы, хотя в Amediateka есть отдельный каталог фильмов.

**Решение:** fetch тянет `/cms/content/movies/` (251 тайтл, включая tv movie), объединяет с сериалами через поле `kind`. В UI добавлен переключатель «Всё / Сериалы / Фильмы». Длительность фильма берётся из `episodes[0].duration` (секунды) и переводится в минуты; колонка «Формат» показывает сезоны или длительность.

**Альтернативы:** отдельная страница фильмов; отдельные фильтры и таблица только для фильмов.

**Trade-off:** статический HTML вырос примерно вдвое; часть «фильмов» — ТВ-фильмы и recap-эпизоды; у двух фильмов нет длительности.
